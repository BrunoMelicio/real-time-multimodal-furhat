# Development rules

- Preserve the recorded conference scene behavior. Change new unified code incrementally; validate with offline regression tests first.
- Do not open hardware, run inference, install dependencies or download models without user authorization.
- Use one main environment. Never commit weights, environments, recordings, participant transcripts, credentials or local rollback notes.
- Native Furhat speech/lip sync is required. Observable movement is not a diagnosis or proof of injury.
- This initial main.py selects individual scenes; do not describe it as the completed unified app until that integration is implemented and tested.
